## Главные вопросы

| Вопрос | Ответ |
| --- | --- |
| Что это? | Учебный проект на C++20: консольный клиент и TCP-сервер. |
| Что умеет? | Проверять доступность сервера и регистрировать пользователей. |
| Какие технологии? | Boost.Asio — сеть, Boost.JSON — JSON, OpenSSL — хеширование паролей, CMake — сборка. |
| Где база данных? | В каталоге `mock_db/users`: один JSON-файл на пользователя. Отдельная СУБД не нужна. |
| Сколько команд за запуск? | Клиент выполняет одну команду и завершается. Для следующей запустите его снова. |
| Есть вход в аккаунт? | Нет. Авторизация и работа с токенами пока не реализованы. |
| С чего читать код? | `ClientMain.cpp` и `ServerMain.cpp`, затем `TcpClient.cpp` и `ClientSession.cpp`. |

## Запуск

Нужны компилятор с поддержкой C++20, CMake 3.16+, заголовки Boost.Asio, библиотека Boost.JSON и библиотека OpenSSL Crypto с заголовками.

Команды ниже выполняются из корня проекта в Linux.

### 1. Собрать

```bash
cmake -S . -B build
cmake --build build --parallel
```

Программы появятся в `build/bin`. При настройке сборки CMake копирует туда конфигурацию и начальную базу пользователей.

### 2. Запустить сервер

```bash
./build/bin/server ./build/bin/EndpointConfig.json
```

По умолчанию сервер слушает `127.0.0.1:8080`. Остановить его можно через `Ctrl+C`.

### 3. Запустить клиент в другом терминале

```bash
./build/bin/client ./build/bin/EndpointConfig.json
```

Введите `healthcheck`. Ожидаемый ответ:

```text
OK: Сервер работает
```

Для регистрации запустите клиент ещё раз и введите `register`, затем логин и пароль. При новом непустом логине ответ будет `OK: Пользователь зарегистрирован`.

Команды не зависят от регистра: `REGISTER` и `/register` тоже работают. Логины зависят от регистра. В начальной базе уже заняты `alice` и `bob`.

Автоматических тестов пока нет: каталог `tests/` пуст, тестовые цели в CMake не заданы. Для ручной проверки выполните `healthcheck`, регистрацию и повторную регистрацию того же логина — она должна вернуть `ERR: Логин уже занят`.

## Структура

```text
.
├── CMakeLists.txt          # Правила сборки клиента, сервера и общей библиотеки
├── EndpointConfig.json    # Адрес и порт
├── client/                # Консольный клиент
│   ├── ClientMain.cpp      # Чтение настроек и запуск
│   └── TcpClient.*         # Подключение, ввод команды, запрос и ответ
├── server/                # TCP-сервер
│   ├── ServerMain.cpp      # Загрузка настроек и базы, запуск
│   ├── TcpServer.*         # Приём подключений и таймеры
│   ├── ClientSession.*     # Обработка одного запроса клиента
│   └── UserDirectoryDatabase.* # Загрузка и сохранение пользователей
├── shared/                # Общий код клиента и сервера
│   ├── EndpointConfig.*    # Адрес и проверка порта
│   ├── EndpointConfigParser.* # Чтение настроек из JSON
│   ├── TextFileReader.*    # Чтение текстового файла
│   ├── ProtocolRequest.h   # Поля запроса
│   ├── ProtocolResponse.h  # Поля ответа
│   ├── JsonRequestParser.* # Разбор запроса
│   ├── RegistrationRequestSerializer.* # Создание JSON для регистрации
│   ├── ResponseParser.*    # Создание и разбор ответа
│   └── CommandUtils.h      # Сравнение команд
├── mock_db/users/          # Начальные записи alice и bob
└── tests/                 # Пока пуст
```

`*.h` описывают классы и структуры, `*.cpp` содержат реализацию. Код из `shared/` собирается в библиотеку `tcp_common`, которую используют обе программы.

## Как работает

1. Сервер читает конфигурацию и загружает пользователей в память.
2. Клиент подключается. Если подключение не удалось, повторяет попытку через 3 секунды.
3. Клиент читает команду из консоли и отправляет JSON.
4. Сервер создаёт `ClientSession` для соединения, разбирает запрос и выполняет команду.
5. Сервер отправляет ответ и закрывает соединение. Клиент выводит результат и завершается.

`io_context` в Boost.Asio — цикл обработки сетевых событий и таймеров. Сервер работает в одном потоке: ожидание подключений, чтение и отправка асинхронные; сохранение пользователя и хеширование выполняются в этом же потоке. У клиента подключение асинхронное, а ввод команды и обмен сообщениями — синхронные, то есть ждут завершения операции.

Каждые 5 секунд сервер выводит общее число принятых подключений, включая закрытые. Каждые 10 секунд — сообщение «Сервер работает».

## Протокол

Каждое сообщение — JSON в одной строке, завершённой переводом строки `\n`. Одно соединение обслуживает один запрос и один ответ.

Проверка сервера:

```json
{"event":"HEALTHCHECK","data":{}}
```

Регистрация:

```json
{"event":"REGISTER","data":{"login":"new_user","password":"example_password"}}
```

Пример ответа:

```json
{"status":"OK","message":"Пользователь зарегистрирован"}
```

В запросе обязательны строка `event` и объект `data`. Для регистрации нужны непустые строки `login` и `password`. Необязательное строковое поле `token` читается, но не используется. Ответ содержит `status` (`OK` или `ERR`) и строку `message`.

## Настройки и данные

```json
{
  "host": "127.0.0.1",
  "port": 8080
}
```

`host` — IP-адрес, который слушает сервер и к которому подключается клиент; `127.0.0.1` означает этот компьютер. Допустимый порт — от `1` до `65535`. Если меняете порт, используйте одинаковое значение для обеих программ.

Путь к конфигурации — обязательный аргумент. По умолчанию сервер ищет `mock_db` рядом с указанным файлом конфигурации. Можно передать другой каталог базы:

```bash
mkdir -p ./build/my_db/users
./build/bin/server ./build/bin/EndpointConfig.json ./build/my_db
```

Каталог `users` должен существовать. Отсутствующая база или некорректная запись пользователя останавливают запуск сервера.

Запись хранится в `users/<uuid>.json`, где UUID — уникальный идентификатор пользователя. Поля: `uuid`, `login`, `password_hash`, `token_hash`. При регистрации `token_hash` остаётся пустым. Пароль сохраняется как хеш PBKDF2-HMAC-SHA256 со случайной солью — добавкой, которая делает хеши одинаковых паролей разными.

При запуске по инструкции новые пользователи записываются в `build/bin/mock_db`. CMake копирует начальную базу только при отсутствии этого каталога и не перезаписывает её при повторной настройке. Конфигурацию CMake копирует заново из корня проекта.

Соединение не использует TLS: пароль передаётся по сети открытым текстом и виден при вводе в консоли. Текущая версия предназначена для локального обучения.

## Ошибки

| Сообщение или проблема | Что проверить |
| --- | --- |
| CMake не находит Boost или OpenSSL | Установлены ли библиотеки и их заголовки; для Boost нужен компонент JSON. |
| `Cannot open file` | Путь к конфигурации и права на чтение файла. Относительный путь считается от текущего каталога терминала. |
| `Invalid port` | Порт должен быть целым числом от `1` до `65535`. |
| `Address already in use` | Не запущен ли уже сервер на этом порту. Остановите его или выберите другой порт. |
| Клиент повторяет подключение | Запущен ли сервер, совпадают ли адрес и порт. |
| Ошибка сервера при загрузке базы | Существует ли `users`, корректны ли JSON-записи и совпадают ли имена файлов с их UUID. |
| `Некорректный запрос` | Формат JSON, обязательные поля и типы значений. |
| `Не удалось сохранить пользователя` | Подробности в терминале сервера: например, права записи в каталог базы. |
